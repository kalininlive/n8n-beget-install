# AGENTS.md — установка стека агентом (Claude Code, Codex, Cursor и др.)

Инструкция для ИИ-агента, которому пользователь поручил «поставить n8n из этого репозитория». Человеку достаточно README.

## Что должно получиться

На сервере Ubuntu в `/opt/n8n-install` — запущенный стек: n8n по HTTPS на домене пользователя, админ-бот в Telegram, движки рендера, локальный Telegram Bot API (если даны ключи), шрифты `/opt/fonts`. Итог проверяется командой `bash /opt/n8n-install/install-extras.sh --check` («🟢 Всё зелёное»).

## Шаг 1. Собрать у пользователя данные

Спросите всё одним сообщением. Секреты не выводите в чат повторно и не коммитьте.

| Переменная | Что это | Где пользователь берёт | Обязательно |
|---|---|---|---|
| SSH-доступ | IP, пользователь root (или sudo), ключ/пароль | панель VPS | ✅ |
| `DOMAIN` | домен или поддомен для n8n, A-запись → IP сервера | панель регистратора | ✅ |
| `EMAIL` | email для Let's Encrypt | — | ✅ |
| `TG_BOT_TOKEN` | токен админ-бота | @BotFather → `/newbot` | ✅ |
| `TG_USER_ID` | числовой ID владельца | @userinfobot | ✅ |
| `TELEGRAM_API_ID`, `TELEGRAM_API_HASH` | ключи приложения для Bot API до 2 ГБ | my.telegram.org → API development tools | желательно |
| `PROXY_URL` | HTTP-прокси `http://user:pass@host:port` | провайдер прокси | нет |
| `N8N_ENCRYPTION_KEY` | только при переносе со старого n8n | старый `.env` | нет |

Требования к серверу: **Ubuntu 24.04 LTS** (рекомендуется; также 22.04 и 26.04 LTS), x86_64, от 4 ГБ RAM (рекомендуется 8 ГБ, 4 vCPU), от 25 ГБ свободного диска, свободные порты 80/443.

## Шаг 2. Проверить DNS

```bash
getent ahostsv4 "$DOMAIN"        # должен совпасть с IP сервера
```

Если не совпадает — попросите пользователя поправить A-запись и подождать. Без этого SSL не выпустится (стек встанет, сертификат выпустится позже сам).

## Шаг 3. Запустить установку без вопросов

На сервере от root (по SSH без TTY установщик сам переходит в неинтерактивный режим):

```bash
curl -fsSL https://raw.githubusercontent.com/kalininlive/n8n-beget-install/stack-v2/install.sh -o /root/install.sh
DOMAIN='n8n.example.com' EMAIL='me@example.com' \
TG_BOT_TOKEN='123456789:AAH…' TG_USER_ID='123456789' \
TELEGRAM_API_ID='12345678' TELEGRAM_API_HASH='0123456789abcdef0123456789abcdef' \
PROXY_URL='' NONINTERACTIVE=1 bash /root/install.sh
```

- Длится 10–15 минут (готовый образ рендера скачивается с ghcr.io; без доступа к нему — локальная сборка, +20 минут). Запускайте в фоне / через `nohup … &` и читайте `/var/log/n8n-install.log`.
- Чтобы не светить секреты в истории shell, можно положить переменные в файл `chmod 600` и сделать `set -a; . ./answers.env; set +a; bash install.sh`.
- `FORCE=1` — продолжать при предупреждениях (DNS ещё не обновился, мало RAM, не-LTS Ubuntu). Без него установщик в неинтерактивном режиме останавливается на таких предупреждениях — сначала сообщите о них пользователю.
- Коды выхода: `0` — всё зелёное, `3` — стек установлен, но есть замечания проверки (см. конец журнала), `1` — остановка до установки (причина в последней строке `❌`).

## Шаг 4. Проверить и отчитаться

```bash
bash /opt/n8n-install/install-extras.sh --check
curl -fsS https://$DOMAIN/healthz
```

Сообщите пользователю: адрес n8n, что при первом входе нужно создать аккаунт владельца, что в кредах Telegram в n8n Base URL = `http://telegram-bot-api-proxy`, и что `N8N_ENCRYPTION_KEY` из `/opt/n8n-install/.env` нужно сохранить в надёжном месте (без него не расшифровать креды из бэкапа). Само значение ключа в чат не выводите — пусть пользователь заберёт его сам.

## Частые проблемы

| Симптом | Что сделать |
|---|---|
| `Порт 80/443 занят` | на сервере стоит nginx/apache из шаблона хостинга: `systemctl disable --now nginx apache2` (с согласия пользователя) |
| SSL не выпускается | DNS ещё не указывает на сервер; после исправления: `docker restart n8n-traefik` |
| не скачалась модель whisper / образ рендера | нет доступа к huggingface.co / ghcr.io — задать `PROXY_URL` в `.env`, затем `bash install-extras.sh` |
| `telegram-bot-api` не запущен | пустые `TELEGRAM_API_ID/HASH` в `.env` — вписать и `bash install-extras.sh` |
| мало памяти при сборке | установщик сам создаёт swap 4 ГБ при RAM < 8 ГБ; при 2 ГБ RAM стек не потянет рендер |

## Чего не делать

- Не менять `docker-compose.yml` и Dockerfile без просьбы пользователя: новые сервисы — только в `docker-compose.override.yml`.
- Не генерировать новый `N8N_ENCRYPTION_KEY` на сервере, где n8n уже работал: пропадут все креды. Повторный запуск установщика берёт ключ из существующего `.env`.
- Не публиковать содержимое `.env`.
