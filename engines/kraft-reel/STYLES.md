# Как добавлять цвета, декор, форматы, стили и сцены kraft-reel

Пять уровней. Чем ниже, тем реже меняется и тем строже проверка. Всё, что можно сделать данными, делается данными.

| Уровень | Что меняет | Где живёт | Код? | Кто решает |
|---|---|---|---|---|
| **1. Цвет** | акцент (кнопки, свечения, графики, лучи) или вся палитра | профиль клиента `kraft.accent` / `skins/<id>.json` | нет | клиент / мы |
| **2. Декор** | какие пейзажи, сколько птиц, солнце, облака | `styles/<id>/style.json` → `decor` | нет | мы |
| **3. Формат** | какие сцены разрешены агенту, лимиты | `formats/<id>.json` | нет | мы |
| **4. Стиль** | визуальный язык: палитра + декор + вёрстка (CSS) + набор сцен | `styles/<id>/` (`style.json`, `style.css`) | CSS | мы, **утверждает владелец** |
| **5. Сцена (компонент)** | новый тип сцены | `catalog.mjs` + `validate.mjs` + `render.mjs` | JS | мы, утверждает владелец |

Агент-режиссёр в n8n (воркфлоу 57) узнаёт о стиле и формате из `kraft-reel catalog --md --style <id> [--format <id>]` при каждом запуске —
промпт руками не правится. В меню бота стили попадают скриптом `moy-n8n/scripts/kraft-styles-genesis.mjs` (только `status: "approved"`).

## 1. Цвет (без кода)

- **Клиенту под бренд — один цвет.** В его `mascot/profile.json`: `"kraft": { "accent": "#1E6BFF" }`. Светлый и тёмный оттенки,
  бледный (для появления слов) и свечения считаются сами (`styles.mjs → accentSet`). Если белый текст на акценте не читается
  (контраст < 3, например жёлтый), акцент затемняется, в `warnings` рендера пишется предупреждение.
- **Готовая палитра.** `skins/<id>.json` — все поля как в `skins/kraft.json` (фон `bg1..bg3`, текст `ink/muted/pale`, окна `win/panel`,
  подпись `cap`, «бумажный белый» `paper`, текст на тёмном `onDark`, линии пейзажа `line`, акцент `acc` …). В профиле клиента: `"kraft": { "skin": "<id>" }`.
- **Разово в плане:** `"skin": "<id>" | "#RRGGBB"`, `"colors": { "acc": "#…", "bg1": "#…" }` — точечная замена поверх скина.

## 2. Декор (без кода)

В `styles/<id>/style.json`:
```json
"decor": { "landscapes": ["city", "village", "park"], "birds": [4, 5], "sun": 0.6, "clouds": 2 }
```
`landscapes` — из каких наборов собирается пейзаж сцены (соседние сцены всегда разные); `birds` — сколько стаек (от–до, `null` — без птиц);
`sun` — вероятность солнца; `clouds` — 0–2. Новый набор пейзажа (например, «горы» или «море») — это уже код: пропы в `lib/city.mjs → PROPS` и режим в `MODES`.

## 3. Формат (без кода)

`formats/<id>.json`:
```json
{ "id": "short", "name": "Короткий (до 25 с)", "description": "Хук → одно-два окна с доказательством → призыв.",
  "components": ["hook_link", "window", "question", "cta"], "rules": { "max_scenes": 5 } }
```
Разрешены сцены = сцены стиля ∩ сцены формата. Валидатор не пропустит сцену вне списка и лишние сцены. Клиенту по умолчанию —
`"kraft": { "format": "short" }` в профиле, иначе `default_format` стиля.

## 4. Стиль

1. **Эталон.** Пилот нового вида (как `genesis-n8n/pilot/mascot-paper/`): референс → покадровый разбор → HTML-пилот → ролик → владелец смотрит.
   Без утверждения стиль не попадает ни агенту, ни в меню.
2. **Папка** `styles/<id>/`:
   - `style.json` — `id`, `name`, `status: "draft"`, `menu: { title: "🌙 Название", intro: "одна строка для меню" }`, `description` (что видит зритель — для агента),
     `fits` (когда подходит), `skin`, `css` (свой `style.css` или `../kraft/style.css`), `default_format`, `decor`, `components`;
   - `style.css` — вёрстка. Цвета — только токенами `${acc}`, `rgba(${accRgb},.3)`, `${paper}` … (список — в `skins/kraft.json` и `styles.mjs`),
     иначе смена акцента клиента не перекрасит элемент.
   Пример стиля **без единой строки кода** — `styles/kraft-night/` (своя палитра, декор, общий CSS Крафта).
3. **Проверка без бота:**
   ```bash
   node cli.mjs styles --all                                   # стиль виден, поля читаются
   node cli.mjs catalog --md --style <id>                      # что увидит агент
   # рендер плана пилота в новом стиле (черновик — только с --draft):
   mkdir -p /tmp/j && cp tests/pilot/* /tmp/j/ && node -e "const f='/tmp/j/plan.json',p=require(f);p.style='<id>';require('fs').writeFileSync(f,JSON.stringify(p))"
   node cli.mjs render /tmp/j --out /tmp/j/<id>.mp4 --draft
   ```
   Регресс: план `tests/pilot` в стиле `kraft` должен собираться в тот же HTML, что и до правки (сравнить `buildHtml` старой и новой версии).
4. **Утверждение.** Владелец смотрит ролик → `status: "approved"`, `approved: "<дата>"` → коммит в `stack-v2` → push.
5. **Выкатка:** `npm run deploy:kraft-reel -- [--env .env.client-<имя>] --test`, затем меню бота:
   `node scripts/kraft-styles-genesis.mjs --apply` (для клиента — `--env .env.client-<имя>`). Кнопка стиля появится в «🔥 Маскот» рядом с «🟫 Крафт»,
   режимы Ручной / Авто / Голос — сразу. Статусы нового стиля: `KRAFT_TEXT:<id>`, `KRAFT_LLM:<id>`, `KRAFT_VOICE:<id>`.
6. **Убрать стиль:** `status: "draft"` (или удалить папку) → выкатка → `kraft-styles-genesis.mjs --apply` — ноды стиля удалятся из меню.

## 5. Сцена (компонент, с кодом)

1. `catalog.mjs` → `COMPONENTS`: `duration`, `use` (одна фраза для агента — когда брать), `fields` (тип, лимиты, `required`, `note`).
2. `validate.mjs` — особые проверки полей, если лимитов из каталога мало.
3. `render.mjs` → `sceneBody`: разметка + таймлайн GSAP. Моменты появления — `wordTime(sc, фраза)` (по словам диктора), текст по словам — `words()`.
   Цвета — только `C.*`. Никакого `Math.random`/`Date.now` — только `R()` (seed).
4. Добавить сцену в `components` нужных стилей и форматов.
5. Сверка: `npx hyperframes lint` (0 ошибок) + `hyperframes snapshot` по ключевым секундам + владелец смотрит ролик.

## Версия

После любой правки движка — поднять `version` в `package.json` (0.x.y: y — исправление, x — новый стиль/формат/сцена). Версия видна в
`kraft-reel --version` и в ответе рендера — по ней видно, что стоит у клиента.
