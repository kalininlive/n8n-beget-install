# Как добавлять цвета, стили, форматы и компоненты MONTAGE v2

Четыре уровня. Чем ниже, тем реже меняется и тем строже проверка.

| Уровень | Что это | Кто задаёт | Где живёт | Нужен код? |
|---|---|---|---|---|
| **Цвет (скин)** | палитра ролика | клиент в бренд-ките, или LLM выбирает сама | план (`"skin": "#E53935"`) или `skins/<имя>.json` | нет |
| **Формат** | какие компоненты разрешены и зачем (сценарный шаблон) | мы | `formats/<id>.json` | нет |
| **Стиль** | визуальный язык: шрифты, формы, анимации, раскладки | мы, утверждает владелец | `styles/<id>.json` + код в `render.mjs` | да |
| **Компонент** | тип сцены (круг, чек-лист, слайд…) | мы, утверждает владелец | `catalog.mjs` + код в `render.mjs` + валидатор | да |

Агент-режиссёр в n8n узнаёт обо всём из `montage-v2 catalog --md`. Воркфлоу вызывает команду при каждом запуске и вставляет ответ в системный промпт,
поэтому новый стиль, формат или компонент агент видит сразу после выкатки движка, промпт руками не правится.

## Цвет

- Любой цвет `"#RRGGBB"`: светлая и тёмная части градиента, тёмный фон, приглушённый текст и карточки считаются в `skins.mjs` (`derive`).
  Из `#1E6BFF` получается палитра эталона с точностью 1–2 единицы.
- Если белый текст на цвете бренда нечитаем (контраст < 3, например жёлтый), цвет затемняется, в `warnings` пишется предупреждение.
- Готовый скин с ручной палитрой: `skins/<имя>.json` (все поля как в `brand_blue.json`), в плане `"skin": "<имя>"`.
- Кто выбирает цвет — решает бренд-кит клиента (см. `moy-n8n/MONTAGE_V2.md`):
  `colorMode: "fixed"` — воркфлоу передаёт `--skin "#цвет клиента"`, план агента не важен;
  `colorMode: "agent"` — агент пишет `"skin"` в план сам (например, под тему ролика), валидатор проверит формат и контраст.

## Формат (без кода)

`formats/<id>.json`:
```json
{ "id": "list_top", "name": "Топ-N: пункты по очереди", "style": "reference",
  "description": "Хук → 3–5 пунктов (card_over_blur / slide_full) → итог → призыв",
  "components": ["talking", "slide_full", "card_over_blur", "speaker_circle", "cta"], "rules": {} }
```
Валидатор не пропустит компонент вне списка. Проверка: `montage-v2 validate` на двух-трёх планах, затем рендер одного.

## Стиль (с кодом)

1. **Эталон.** Собрать пилот стиля (HyperFrames-композиция, как `genesis-n8n/pilot/montage-v2/`), владелец смотрит и утверждает. Без утверждения стиль не выкатывается.
2. **Описание.** `styles/<id>.json`: `id`, `name`, `description` (что видит зритель, для агента), `fits` (когда подходит), `components`, `status: "draft"`.
3. **Код.** В `render.mjs` ветвление по `plan.style` для отличающихся частей: шрифты, кегли, формы плашек, позиции, твины.
   Общая механика (слой спикера, маска, размытие, b-roll, субтитры) переиспользуется.
4. **Сверка.** План эталона стиля → `montage-v2 render` → `ssim.sh` против эталонного ролика (цель ≥ 0,975, на переходах смотреть лист кадров).
   Прогнать все старые стили: у `reference` на `tests/ref31` должно остаться кадр в кадр (SSIM 1.0000 к прошлой версии).
5. **Утверждение.** Владелец смотрит side-by-side → `status: "approved"` (агенту видны только утверждённые) → коммит → выкатка.

## Компонент (с кодом)

1. `catalog.mjs`: запись в `COMPONENTS` (`dur`, `fields`, `obj`, `use` — одна фраза для агента, когда его брать).
2. `validate.mjs`: проверки полей и автопривязка `*_at`, если в компоненте есть появления по словам.
3. `render.mjs`: поза спикера (в цикле `scenes.forEach`) и графика (`sceneGraphics` для ASS или `slideHtml` для HyperFrames, если сцена без спикера).
4. Добавить компонент в `components` нужных стилей и форматов.
5. Сверка с эталоном, как для стиля.

## Версия

После любой правки поднимать `version` в `package.json` (0.x.y: y — исправление, x — новый стиль, формат или компонент). Версия есть в ответе движка,
по ней видно, что стоит у клиента.
